PRD & Design Reference · v1.0

CORE.
Measure what you move.

A daily stretching and core-strength mobile webapp. Each exercise feeds a measurable KPI — touch your toes, hold a 60s side plank, reach your ear to your shoulder — each scored 1–5. The daily ritual stays calm. The measurement layer makes it mean something.

Mobile webapp Vercel-hosted Portrait only iOS + Android PWA installable Offline-first JSON backup
How to use this document
This is a single feedable reference for designers, engineers, and AI design tools (claude.design). Sections are self-contained. Every screen has a written spec and an inline mockup. Design tokens are in §3. Tech constraints in §4. The Area × KPI × Exercise master table is in §7.
§ 1

Design principles

Non-negotiable. Every screen, every word, every animation must pass these.

  1. Simple before clever. If a screen has more than one primary action, it’s too complex.
  2. Friendly, never clinical. The KPIs are clinical underneath. The voice the user hears is not. “Nice — your forward fold is improving,” not “F1 score increased 2→3.”
  3. Daily ritual is sacred. The calm 4–8 minute habit is why people return. Nothing disrupts that loop.
  4. Progress is always one tap away. From any screen, see CORE Index and KPI trends.
  5. Measurement is the seasoning, not the meal. Big once at onboarding, light every two weeks after.
  6. No nagging. Re-measurement prompts are gentle. Streaks don’t shame. Lapses welcomed warmly.
  7. Forgiveness everywhere. Easy skip, pause, resume, undo.
  8. One screen, one job. No tabs inside screens, no multi-step forms on a single view.
  9. Your data is yours. One tap exports everything as JSON. One tap imports it back. No account required to start.

Spacing & radius

Base unit 4px. Common: 8, 12, 16, 20, 24, 32, 48, 64. Inside phone screens, body padding 20px. Card padding 14–18px. Section gaps 16px.

Cards 14–16px radius. Hero cards 22px. Small chips 12px. Pills/buttons 100px (fully rounded). Phone screen mask 34px.

Motion

  • Page transitions: 240ms cubic-bezier(0.2, 0.8, 0.2, 1). Slide-right forward, fade for tabs.
  • Routine auto-advance: 400ms cross-fade between exercises.
  • Radar polygon fill: 600ms ease-out. Axes draw counterclockwise over 400ms first.
  • Score reveal: 300ms scale-up from 0.85, ease-out. No bounce.
  • Re-measure banner pulse: 2s gentle opacity loop 0.6 → 1.0.
  • Never: spring animations on critical UI. No celebratory confetti. No sound effects beyond a soft transition ding.

Icons

Line icons, 1.5px stroke, rounded line-caps and line-joins. 22px in tab bar, 16–20px elsewhere. Anatomical icons (Area cards) are highly abstracted.

Illustrations

Cartoon figures inside circles, in the spirit of Bend. Warm skin tones, simple hair, colorful athletic wear (default outfit: coral-red top + dark-blue pants). White motion arrows where relevant. Always inside a soft pastel circle that rotates by Area.

§ 4

Technical specification

Platform

  • Mobile webapp, served from Vercel.
  • Portrait orientation only on both iOS and Android. Lock via CSS @media (orientation: landscape) with a polite "rotate your phone" screen — no landscape experience.
  • PWA-installable with manifest + service worker. iOS Add-to-Home-Screen supported. Android install prompt supported.
  • Offline-first. All exercises, KPIs, and content bundled at build time. App works fully without a network.
  • No account required to start. Local-first storage. Account is optional, for cross-device sync (V2 only).

Recommended stack

LayerChoiceWhy
FrameworkNext.js 15 (App Router)Vercel-native; static export possible; PWA-friendly
LanguageTypeScriptSchema safety for JSON import/export
StylingTailwind + CSS variablesToken-driven; design system as CSS vars
StateZustandLightweight; persists to IndexedDB
StorageIndexedDB via idb-keyvalLarger than localStorage; survives PWA reinstalls
AnimationFramer MotionRight level for the calm motion we want
ChartsCustom inline SVGRadar + sparklines simple enough to hand-roll; no 200KB dep
Pose (V2)MediaPipe Tasks (web)Runs in-browser; no backend; privacy-preserving

Mobile webapp constraints

  • Viewport: <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover, user-scalable=no">
  • Safe areas: use env(safe-area-inset-top/bottom/left/right) for all chrome. Tab bar always includes bottom inset; runtime player includes top inset.
  • iOS rubber-band: overscroll-behavior: none on body; scroll inside containers.
  • No-zoom inputs: all <input> ≥16px font-size to prevent iOS auto-zoom.
  • Tap targets: minimum 44×44 px (Apple HIG).
  • Status bar: manifest theme-color: #0a0a0f matches background; apple-mobile-web-app-status-bar-style: black-translucent.
  • Install prompt: only after first completed routine. Never on first launch.
  • Wake lock: request screen-wake-lock during routine player so the screen doesn't dim mid-stretch.
  • Audio: short transition ding (~200ms) at exercise change. User can mute. No music — let users run their own.
  • Landscape lock: CSS-only — at @media (orientation: landscape), show a rotate-icon screen with "CORE works best in portrait."

Performance budgets

  • Initial JS bundle: under 150 KB gzipped.
  • Time-to-interactive on a mid-tier Android (Moto G6 equivalent): under 2.5s on 4G.
  • Routine player must hit 60 fps on exercise transitions.
  • All exercise illustrations: inline SVG (no PNG/JPG). Total illustration weight under 80 KB.

Vercel deployment

  • Static export (output: 'export') where possible to maximize CDN cacheability.
  • Preview deployments on every PR.
  • One env var: NEXT_PUBLIC_APP_VERSION shown on Profile screen.
  • Analytics: Vercel Analytics (privacy-preserving, cookieless). Plausible as a deeper alternative.
  • Custom domain on first launch (e.g. core.app or chosen domain).

Browser support

  • iOS Safari 16+ (covers iOS 16–18+, ~95% of active iPhones).
  • Chrome on Android 110+.
  • Samsung Internet 22+.
  • Desktop: not supported. Visiting on desktop shows a "scan QR to open on your phone" landing page.
§ 5

Data model + JSON I/O

All user data lives client-side in IndexedDB. A single JSON file exports everything for backup, or imports to restore. This is the user’s primary backup mechanism — there is no cloud account in V1.

Storage architecture

  • IndexedDB via idb-keyval (one keyspace).
  • Single top-level key: core_data_v1 containing the full state object.
  • Auto-save on every meaningful state change (debounced 500ms).
  • Schema version field guards against breaking changes; migrations run on import.

Export / Import — user flow

From the Profile screen:

  • Export: "Download my data" → serializes the full state, downloads as core-backup-YYYY-MM-DD.json. iOS uses Web Share API; Android uses standard file download.
  • Import: "Restore from backup" → file picker → validates schema → confirmation diff ("This will replace 47 measurements with the ones in your backup. Continue?") → restores.
  • Merge mode (V1.5): combine current + backup, keeping the newest of any conflicts.
  • Auto-prompt: after every 30 days of activity, gentle Profile-screen card: "Want to back up your progress?"

Privacy note
The exported JSON contains only what the user typed at onboarding (age, sex, optional name) plus their measurements and timestamps. Tell users this clearly on the Export screen. No third party ever sees it unless the user shares it themselves.

Schema migration

Every schema version increments $schema. On import of an older version, run a migration chain (v1 → v1.1 → v1.2…). Never drop data silently; surface anything that can’t be migrated to the user.

§ 6

User flows

Onboarding (12 min with Measure Tests, 3 min without)

  1. Welcome. Splash with wordmark + tagline. Get Started / Sign In.
  2. CORE info. Age, sex, height, weight (optional), activity level, injury checkboxes.
  3. Pick what you want to improve. 15-area grid; multi-select. Min 1, recommended 3–5.
  4. Measure Tests intro. What’s coming, equipment, time.
  5. Measure Tests session. Sequential per-KPI; three modes (manual/guided/auto).
  6. Baseline reveal. Radar fills in; CORE Index lands; weakest-link nomination.

Daily loop (the 95%)

  1. Open app → Home.
  2. Today’s routine card sits at top — already chosen, with duration + areas + KPIs.
  3. Tap Start. Runtime player opens.
  4. Stretch for 4–15 minutes. Calm circles, gentle timer, prev/pause/next.
  5. "Nice." Complete screen shows what was just moved.
  6. Tap Done. Back to Home.

Periodic measurement (~14 days, opt-in)

  1. Banner on Home: "3 KPIs ready to re-measure — about 4 min."
  2. Tap "Quick check."
  3. Stale KPIs walked through one at a time.
  4. Scores update; trend lines refresh; back to Home.

Progress exploration

  1. Tap Progress tab (or the CORE Index on Home).
  2. See CORE Index, radar, streaks, full KPI list.
  3. Tap any KPI row → KPI Detail (score, history line, asymmetry, exercises that feed it).

Backup / restore

  1. Profile tab → Data & Backup.
  2. "Download my data" → JSON file saved.
  3. To restore: same screen → "Restore from backup" → file picker → confirm replace.

§ 9

Screen specifications

Every screen in V1. Each has a written spec; mockups are inlined in §10.

Navigation

Four-tab bottom bar: Today / Routines / Progress / Profile. No "Measure" tab. Measurement is something you do from Progress or onboarding, not a primary destination.

1. Home (Today)

  • Greeting — "Good morning, [name]" + practice day counter.
  • Hero card (~45% viewport) — today's routine. Pastel background rotates by Area. Friendly illustration. Title, duration, areas. Single black Start pill.
  • Progress strip — dark card. CORE Index numeral on left, horizontally-scrolling KPI chips on right. Each chip: name, score, sparkline.
  • "Try something else →" text link.
  • Re-measure banner when stale — dismissable, never pushy.

2. Routine Player (Runtime)

  • Black background.
  • Top bar: X (close), "3 of 8" counter, Free badge.
  • Large pastel circle (~55% vertical), friendly cartoon stretch illustration inside. Thin teal progress arc on outer ring shows position in routine.
  • Swap icon (centered), exercise name with (i) info button.
  • Very large countdown timer.
  • Three circular buttons: prev, pause/play (larger, white), next.
  • Wake lock active — screen stays on.

3. Routine Complete

  • "Nice." headline.
  • Session summary: stretches, minutes, areas.
  • Progress sneak — small chips of KPIs this routine nudged. The moment that proves the daily ritual matters.
  • Two CTAs: Done (primary), "Re-measure one of these?" (secondary).
  • No fireworks. No badges flying in.

4. Progress

  • CORE Index hero card (large numeral, delta from baseline, mini radar).
  • Two streaks side-by-side (Practice + Improvement; latter emphasized).
  • KPI list — each row: name, score, sparkline, trend. Filter chips.
  • Bottom-pinned Re-measure button.

5. KPI Detail

  • Title + plain-language description.
  • Hero score block (current 1–5, band label, delta vs baseline).
  • Score band visualization (5 segments).
  • History line chart (90 days default). Annotation pins for routine changes.
  • Asymmetry card when applicable — L/R bars, warm coral if asymmetric.
  • Bottom-pinned Re-measure button.

6. Baseline Reveal (onboarding hero moment)

  • "Baseline complete" eyebrow.
  • Animated radar fills in axis by axis (400ms) then polygon (600ms).
  • CORE Index lands in the center.
  • Weakest-link card: "Your weakest link is X — let's start there."
  • Single CTA: "Build my first routine."

7. Area Selection

  • Onboarding step 3 of 6.
  • 2-column grid of 15 Area cards.
  • Each card: anatomical line icon, area name, one-line KPI subtext.
  • Selected = teal border + check badge + pastel gradient.
  • Counter at bottom: "5 areas selected · recommended 3–5."

8. Measure Test

  • Progress segment bar at top.
  • KPI title + plain-language description.
  • Video demo of correct form.
  • Setup checklist (tappable).
  • Measurement input: large numeric, unit toggle, "How to measure" link.
  • Record Score CTA.
  • Three modes available: manual / guided / auto pose-estimation.

9. Profile (with Data & Backup)

  • Name + avatar placeholder.
  • CORE info: age, sex, height, weight, activity — editable.
  • Areas & KPIs section.
  • Data & Backup section — Download my data (JSON export); Restore from backup (JSON import); "Last backup: 14 days ago" if applicable.
  • Preferences: reminder time, units, voice prompts, transition sounds.
  • About: version, privacy policy, support.

Risks & mitigations

IDRiskMitigation
R1Onboarding too heavy — Measure Tests scare users offAllow "Skip for now" on the Measure Tests intro. App still works without a baseline, just shows empty Progress with a gentle CTA to come back.
R2Self-administered tests are noisy — users distrust the scoreThree modes (manual / guided / auto) with explicit "How to measure" links. Show trend over single value — one outlier doesn't change the story.
R3Measurement framing encourages disordered exerciseVoice rules: never "below average" or "behind." Scores 1–2 framed as "room to grow," not deficits. No leaderboards, no public sharing in V1.
R4Plateau churn — user stops improving and quits"Improvement streak" recognizes any KPI nudge, not absolute progress. Routine engine rotates targets to avoid plateauing on the same KPI.
R5Pose estimation accuracy in V2Always offer manual fallback. Show confidence indicator. Don't gate the score on auto-detection.
R6Data loss — user wipes browser / loses phoneJSON export is the V1 backup. Auto-prompt every 30 days. V2 adds optional cloud sync.
R7iOS PWA limitations (no push, limited storage)In-app reminders only in V1 (visible when user opens the app). For richer notifications, native app is V3.
